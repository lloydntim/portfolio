**Owner:** Lloyd Ntim

**Purpose:** Provide concise public copy that explains the AI-driven developer workflow demonstrated by this repository without claiming a runtime automation agent.

## 1. Recommended public section

### Eyebrow

HOW I WORK

### Heading

Agentic engineering with human accountability

### Introduction

I use AI coding tools inside a specification-driven engineering process, not as a substitute for product judgment or technical ownership. Requirements, architecture, security decisions and releases remain human-controlled, while Claude Code, Codex and Copilot support planning, implementation, testing and review.

### Step 1

**Frame and specify**

Define the user problem, scope, constraints and observable acceptance criteria before material implementation begins.

### Step 2

**Build within boundaries**

Give the implementation agent a bounded objective, relevant repository context, explicit permissions and a clear completion condition.

### Step 3

**Verify independently**

Use type checks, tests, browser validation, accessibility scans and a separate review context to challenge generated changes against the approved specification.

### Step 4

**Release and learn**

Keep pushes, merges and production releases human-approved, then turn failures and useful patterns into reusable team guidance.

### Evidence statement

This portfolio was delivered through that workflow. Claude Code supported implementation, Codex provided independent architecture and code review, and I retained responsibility for scope, decisions, quality and release approval.

## 5. Accuracy boundary

The public site may claim experience integrating an AI-driven developer workflow because this repository contains operating instructions, workflow documentation, architecture decisions, AI-attributed commits, automated tests and pull-request history.

The site should not claim that this portfolio is itself:

- A runtime automation agent.
- An Agent SDK application.
- A multi-agent production service.
- A cloud-hosted autonomous coding system.

Those would require separate runtime architecture, tools, state, guardrails, tracing, evaluations and deployment evidence.
